# SSH controller feasibility slice

The Desktop migration uses a finite Python process behind system OpenSSH. The Mac runs Node and holds model credentials. The process receives a nonsecret model snapshot, builds the existing `AgentApp`, attaches the existing session registry and projects its events through the existing Desktop projector. It opens no product HTTP port. This is a Stage 1 implementation; the released Desktop still uses its existing modes until later migration stages pass.

## Stage2 transport and configuration

The production Desktop path selects SSH stdio and refuses the legacy HTTP transport. `desktop/chat_service.py` is the shared coordination layer for that controller and the retained HTTP compatibility facade. Session, approval, job, run and durable event managers keep their existing authority. The controller does not introduce another scheduler or terminal-state table. Job event pages read the existing store, detect retained-history gaps and carry its terminal snapshot; Mac stream cursors bind authority, workspace and job identity. Usage is a read-only projection of completed durable exchanges, with reported usage summed once rather than reconstructed from a Mac message cache.

The Mac stores six role profiles and model credentials through its existing AES-GCM codec and native safeStorage-wrapped data key. This model path refuses a missing secure codec and has no plaintext fallback. Public profile snapshots contain effective model, context/output limits, temperature, connection/overall timeouts and SDK retry settings. The original SDK default of five retries and engine generation ceiling of three attempts remain separate layers; deterministic provider tests keep zero SDK retries. The summary wrapper retains its existing 90-second outer limit, which can shorten a larger role SDK timeout. The bridge adds no retry layer. Title calls bind the accepted parent turn; provider tests have their own fixed session scope.

The owned Next model worker may receive proxy settings in its private Mac startup environment. Ordinary subprocesses and SSH children receive a closed environment allowlist. Proxy endpoints, userinfo and authentication never appear in remote snapshots. Undici 7.25.0 supplies public dispatchers, exact connect cancellation and the existing NO_PROXY behavior. Each proxied model request owns its dispatcher and selects the authentication identity for its fixed endpoint protocol; cancellation does not close another request's dispatcher. The Mac overall deadline remains absolute across headers and reads.

Model-key protection remains the known-secret byte boundary established in Stage1. Proxy authentication adds a separate bounded category: at most six distinct model keys and four raw proxy protection values, each at most 8 KiB, with total raw bytes at most 64 KiB. Deduplicated raw/URI/JSON/base64 variants and complete proxy URI/Basic authentication forms occupy at most 512 KiB per bridge (at most six role copies). This is a Mac allocation guard, not an increase to remote installation or RSS budgets. Derived URI variants can require up to three times a raw item's bytes, as before; the unfinished prefix cannot exceed the longest admitted variant. Provider chunks remain at most 1 MiB and emitted chunks 32 KiB. If no printable UTF-8 mask byte is available, configuration fails before dispatcher construction.

A short proxy password can equal public JSON/SSE syntax. Its actual Basic authentication material is protected, while unrelated normal model content stays opaque. Non-success HTTP diagnostics are replaced with status-derived safe documents. For proxied success responses, only explicit top-level JSON error documents and SSE error diagnostics are replaced with a bounded safe DTO; normal choices, tools and usage are not decoded or rewritten. Complete authentication material and long raw proxy values receive cross-chunk filtering. This does not promise to classify an arbitrary normal model answer that disguises a short proxy value as ordinary content. Sensitive headers are not forwarded; remaining allowed headers retain the existing constrained reconstruction. The typed diagnostic frame buffer is capped at 512 KiB and complete SSE terminators do not wait for upstream EOF.

Stable ingress uses one configured installation identity. An accepted request can only be observed again; it cannot obtain another model grant or execute a second time. A durable event may produce several stable subframes, and a reconnect can replay that event without skipping its remaining terminal frames. Mac drafts, title CAS, configuration and file grants remain local metadata. Confirmed messages, usage and job state remain remote authority. A private startup handshake and trusted main-process request proof protect local APIs; Origin checks are an additional boundary rather than authentication.

Automatic controller/science supply and persistent external jobs remain Stage3, Notebook/kernel/attachments/MCP recovery Stage4, and consistent state migration, packaging and old-mode deletion Stage5. Fixture HTTP responses passing through actual SDKs and OpenSSH prove the transport contract; they do not establish external vendor credential acceptance, signed release validity or Intel/Slurm execution.

## Shared behavior

`build_app` remains the single registry, permission, hook, budget, memory and subagent composition root. A deployment can supply model limits and disable Notebook services. `WorkspaceKernelBinding` forwards an explicitly selected science interpreter to the existing kernel manager. CLI defaults remain unchanged.

`JobsManager(register_default_runners=False)` provides the existing job store, run projections, approval broker and events without constructing `SkillApiRunner` or a fallback kernel. `ExternalScriptRunner` demonstrates the runner seam with an independent science process. Its Stage 1 lifetime is a foreground child of the job task. Durable background submission and reconciliation are Stage 3 work; a new process alone does not make a job survive controller shutdown.

The controller adds admission receipts to `DurableTurnEventLog` and uses them in `SessionRegistry`. A receipt binds a persisted authority/workspace identity, session, source request, canonical payload hash and turn before scheduling. The shared memory database owns two additive tables: `turn_ingress` records admission and `turn_authority_identity` supplies a singleton identity across controller restarts. Neither stores terminal state, a retry decision or a second queue. Receipts remain for the workspace lifetime; removing them requires an explicit archival/migration policy. A copied database retains its provenance identity until migration deliberately assigns a new origin.

Stage2 repair adds `turn_projection_checkpoints` in that same database under W03 and W09. The original observer hashes every raw event it passes to `DesktopChatSSEBody`, including unrendered events and TURN_END usage. Its single immutable checkpoint contains the original stable frame bytes through every EXCHANGE_END subframe. Source metadata and original receipt model/provider remain pinned. EOF or observer detach cannot confirm a terminal. SSH checks `flush_durable()` before broadcasting; write failure cancels the turn and emits a bounded transport fault without a business done frame. CLI/IM retain their optional durable-sink behavior.

Confirmation uses the original Database transaction to compare authority, ingress metadata, continuous source digest and producer generation, then stores coverage and bytes together. SQL count/length checks precede source JSON loading and hashing. Source and frames each remain bounded to4MiB and20,000 records. Snapshot reads return at most64 frames and512KiB per page, with revision/source/frame digest pinned across pages. Wire epoch is added to responses and excluded from stable bytes. Mac recovery checks the full digest and cache conflicts before replaying beyond confirmed coverage; it grants no admission, model call or tool execution.

SSH retains original raw events and adds no pruning operation. Checkpoints use the same Database backup, migration and workspace archival lifecycle. They are disposable while their source remains; an externally removed prefix is recoverable only from a checkpoint confirmed before that removal. A missing source and checkpoint is incomplete history. Future automatic source pruning requires a separate retention review. The schema is additive CREATE TABLE IF NOT EXISTS, with one checkpoint per original turn and no independently chosen terminal or retry state.

Messages use indexed receipt keysets plus user/assistant part, binding their opaque cursor to authority, workspace, session and Mac installation. Latest and older pages read only their bounded receipt window and return chronological messages. Queued/interrupted receipts retain their user part. The production UI uses this cursor while the isolated old HTTP mode retains numeric rowids. SSH export streams chronological keyset pages through the existing local download path, fixing its latest boundary before traversal; it never collects the full conversation array.

Bootstrap initializes that metadata under the workspace fence, closes its temporary database connection, then `build_app` opens the single business connection used by the application. The hello identity and the configured session identity must agree. A headless profile without durable admission refuses activation. Permission selection is included in the admission hash and applied only when the shared registry returns a newly admitted turn. A legal duplicate returns its original turn without changing a later session policy. Each connection observes a turn once; repeated admission does not allocate another observer. After restart, a repeated admission cannot start another turn. Existing turn events and session stores remain the sources of progress and history.

## Model bridge

Both provider adapters accept a public lazy client factory and preserve it through `bind`. The controller factory constructs real vendor SDK clients through their public `http_client` argument. A shared restricted transport carries HTTP status and response bytes over reverse RPC. The Mac chooses the endpoint and credentials from its own settings, enforces model and output limits, refuses remote identity headers and URLs, and cancels in-flight fetches and reads on request cancellation, timeout and EOF. Redirects are refused. The public factory retains `config.max_retries`; the Stage 1 `bridged_provider` uses zero retries for deterministic fixture slices. Production Mac snapshot/config reconciliation and all caller effective retry settings are Stage 2 work. That fixture choice does not establish production retry parity.

Model open and every read share one absolute snapshot deadline. The Python transport passes the remaining budget explicitly rather than inheriting a 120-second RPC default. Close has a separate one-second cleanup allowance; cancellation delivery has the same bounded allowance. Both peers remember at most 128 canceled request identities for at most one hour and accept only one late response for each such identity. Arbitrary unknown responses still terminate the connection. The cancellation frame identifies an existing request handler, revoking Mac fetch/read before headers as well as after stream allocation.

The Mac never relays non-success HTTP diagnostic bodies. It generates a bounded status-derived error document while preserving status, validated retry-after and safe request identifiers. For success bodies and streams, a bounded byte filter masks the configured secret and its URI, JSON-escaped and base64 forms before reverse RPC. It holds only an unfinished prefix of a known secret; ordinary SSE terminators pass without waiting for upstream EOF. The configured secret is bounded to 8 KiB, vendor chunks to 1 MiB and emitted chunks to 32 KiB. These buffers stay inside the frozen RSS budget. This is known-secret filtering, not a new provider codec or content classifier.

The controller profile locks OpenAI 2.33.0, Anthropic 0.125.0 and httpx 0.28.1. Anthropic 1.13.0 was evaluated: it moved to httpx2 and removed the public `temperature` argument used by the current adapter. A small public transport type adapter passed the HTTP construction boundary but did not preserve that API contract. The controller therefore locks the existing codec-compatible SDK until an upgrade passes the same real SDK tests and the full provider suite. This does not change the CLI's dependency declarations. No SDK private implementation or global HTTP alias is modified.

The existing Anthropic adapter drops returned thinking signatures and does not replay thinking blocks. This migration does not claim to fix that behavior. Vendor fixtures exercise actual SDK streaming, usage and close behavior; they are distinct from a live external-model credential check.

The [official SDK migration note](https://github.com/anthropics/anthropic-sdk-python/blob/main/MIGRATION.md) documents the public httpx2 boundary and the process-wide effects of its alias helper. The alternative is an explicit second public HTTP transport type backed by the same RPC bytes; it also needs the current adapter's request-codec change. Reevaluate that small upgrade at each controller dependency release, run both real SDK fixtures and the provider suite, measure the locked environment, and review any behavior or budget change. The selected pin avoids changing every CLI deployment's minimum dependencies merely to supply this component.

## Component and environment boundary

`scripts/build_controller.py` follows internal imports and package initializers, rejects old HTTP server, CLI, channels, launch, legacy surfaces and scientific package imports, then produces a deterministic source ZIP with file hashes. Skill Markdown supplies the catalogue. Algorithms, domain libraries and scientific SDK source belong in a separate science payload. The complete OmicsClaw wheel and its console scripts are not inputs to the controller package.

Base has the model SDKs and YAML parser. Notebook adds the Jupyter client and its transport dependencies. Existing MCP uses the project's stdlib transports and adds no MCP SDK dependency. Neither profile installs ipykernel, NumPy, pandas, AnnData or Scanpy into the control environment. The science interpreter supplies kernels and algorithms.

The first measured Linux x86_64 profiles used an independent CPython 3.11.17 distribution. Dependency locks include hashes. Frozen limits are in `omicsclaw/entry/ssh/profiles/budgets.json`; growth must be investigated rather than changing the limits automatically. Cache, interpreter, code and environments must be reported separately, including logical file sizes so hard links do not hide profile costs. Other architectures require separate validation.

## Lifecycle and authority

Stage3 begins by extending the original jobs and remote_jobs records. `jobs.lifetime` separates local in-process observations from same-host external work; old empty values retain their previous runtime-derived interpretation. Only local in-process rows enter the existing orphan sweep. `remote_jobs.source_request_id/payload_hash/proof_json` hold a pre-launch claim and process/scheduler evidence in the original store. A partial unique request index and BEGIN IMMEDIATE make repeated claims return the same unknown row and reject different canonical hashes or targets. These columns add no scheduler, terminal authority or retry permission.

The metadata migration is additive, and legacy records receive no invented identity. Claims and handles retain the original workspace database backup/archival lifetime, including uncertain outcomes. Process proof binds UID, host/boot, PID birth, process group, session and nonce; handle metadata is immutable in memory and survives JSON round trips. Verified launch/ACK-loss reconciliation, signal fencing, observer shutdown and scientific environment/payload integration are subsequent Stage3 work; the metadata slice alone is not their acceptance.

Stage 1 selects EOF shutdown. A kernel-held workspace file lock prevents another controller writer and releases on process death. No daemon, attach broker, systemd or tmux process is required. Existing session, approval and Notebook ownership logic remains in charge of those resources. The controller lock adds workspace ownership; it does not replace their state machines.

EOF closes model capabilities, stops admission, cancels observations and drains shared state. Reconnection starts a new process and inspects receipts and durable events before any new turn. In-flight model output, approval or uncertain tool work is not replayed automatically. Background science jobs, persistent kernel rehydration, leases and process-identity-aware cleanup require later stages.

Mac SSH profiles, model settings, credentials, local drafts and file permissions are Mac authority. Confirmed messages, turns, jobs, plans, usage and artifact metadata belong to the selected controller workspace. Science files and kernel memory belong to their compute target. Mac views will become rebuildable projections with stable source identity and cursor; the current UI cache has not yet been migrated.

Multi-target work will use a restricted Mac SSH transport broker injected into the existing remote executor seams. Target aliases and roots must match the user's configured capabilities. The controller does not receive Mac private keys or forwarded SSH agents. The first slice uses one controller and one workspace; this does not remove the existing multi-target migration requirement.

## Remaining stage boundaries

Desktop route transport migration, production component supply, all skill form and agent paths, persistent external jobs, Slurm, Notebook restart recovery, MCP credential mapping, data migration, signed release tests and deletion of old modes remain required. Stage 1 evidence establishes the shared-core and SSH seams. It is not a full Desktop acceptance result.

## Frozen scope, estimates and review decision

The named inventory is in `2026-10-14-ssh-controller-inventory.json`. It covers eleven work packages, every provider caller, currently fixed store roots, new schema ownership and full capability profiles. App `docs/ssh-controller-route-authority.json` records 88 actual route files with concrete request/query reads, response expressions and links to shared schemas. Dynamic or streaming responses retain their source links; this inventory establishes planned ownership and records pending migration. It is not a claim that these routes already run over SSH.

The planning intervals are 57–114 person-days for the same-core candidate and 98–196 for a TypeScript control migration with the same science, SSH, recovery and data scope. These are engineering estimates based on the named seams, not observed implementation times. They overlap. The candidate saves the control-language port and its continuing CLI/IM parity work, while both choices still need substantial transport and recovery testing. Exceeding a work package upper bound, adding a resident attach broker, duplicating a business state machine or widening a provider rewrite requires another scope review.

Measured Linux sizes use logical file bytes: independent Python 82.63 MiB, Base environment 25.03 MiB and the representative Notebook client environment 26.21 MiB. The old same-function full-wheel/HTTP environment measured 47.11 MiB on the same Python. Its idle process used 55.75 MiB RSS and started in 1.57 s; the representative Notebook control process used 50.56 MiB and started/executed a cell in 1.29 s. Those different workloads do not prove a universal latency improvement. The Mac/OpenSSH SDK fixture exchange previously peaked at 67.54 MiB control RSS.

The existing selected science environment measured 18,602,924,558 logical bytes. It is user compute infrastructure reused for a representative worker probe, not a fresh minimal science deployment. Installed control, interpreter, component archive/extracted source, bounded cache, scientific environments, extension processes and growing user state/data must stay visible separately. Hard links do not reduce the reported logical environment cost.

Unimplemented full-profile estimates reserve 100 MiB for Python, at most 44 MiB for control dependencies and 4.2 MiB for source, within the existing 160 MiB installed full-control cap. Full RSS has a 155 MiB estimated peak under the 160 MiB cap for the defined bounded control workload; this is not measured. The first complete supplier must stay within 120 MiB download and 80 MiB cache, giving a 240 MiB full installed-control-plus-cache cap. Notebook, MCP/attachments, background science jobs and all enabled capabilities must be measured at their Stage3/4 gates, and the combined promised control profile before release. Unbounded data/results belong to declared state/science locations rather than that installation budget.

The candidate is technically viable for independent Stage1 review: shared business assembly/state machines remain single definitions, public SDK injection works over real OpenSSH, and persistent receipts fence duplicate admission. Production provider settings, named caller/turn capabilities, supply/update, complete route adapters, durable kernels/jobs, all science payloads and legacy-mode deletion remain required. The Stage1 recommendation is conditional on the independent code review and exact verification results; it does not authorize a release or claim final acceptance.
